FEATURED BUILD · 2025

Automated IAM Compliance Notifications

Infrastructure-as-Code compliance watchdog — built with Terraform, running on AWS Lambda.

TerraformAWS LambdaIAMEventBridgeSNS
01 Terraform (IaC) Provisions every resource — Lambda, IAM execution role, EventBridge rule — as versioned code.
→
02 Monthly Trigger An EventBridge scheduled rule invokes the Lambda function on a recurring monthly cadence.
→
03 Policy Scan The function walks IAM roles and policies, checking each against internal security standards.
→
04 Notify Owners Non-compliant policies are flagged and every affected user gets notified automatically.
THE PROBLEM

IAM policy drift was caught reactively — during audits or, worse, after an incident — because checking policies against security standards was a manual, easy-to-skip task.

THE BUILD

Wrote the full stack as Terraform modules: the Lambda function, its IAM execution role scoped to read-only policy access, and an EventBridge rule firing once a month. One terraform apply ships the whole watchdog.

THE IMPACT

Compliance checking moved from "whenever someone remembers" to a guaranteed monthly pass — shrinking the audit window and cutting security risk with zero added engineering overhead.

FEATURED BUILD

Ops Inspector — Unified Data & Manifest Query Tool

A local, offline tool that replaces one-environment-at-a-time database lookups and manual manifest pulls with a single browser UI.

PythonMongoDBAWS S3pandasopenpyxl
01 Local Server Double-click launch — Python's standard-library ThreadingHTTPServer serves a browser UI on 127.0.0.1. No framework, nothing touches the internet.
→
02 Smart Field Discovery Type a short field name; the tool samples the oldest and newest records to resolve the full nested path, flagging anything ambiguous instead of guessing.
→
03 Parallel Query Searches all four ingest environments at once, each on its own thread, with live progress and a Stop control that never leaves a partial result.
→
04 Filter, Dedupe & Export AND/OR filter builder, "active asset" window checks, duplicate removal, saved searches, and CSV export or a Compass-ready query copy.
THE PROBLEM

Answering "where is this asset, what state is it in, is it live for this period" meant opening a database GUI one environment at a time, typing exact nested field paths by hand, and cleaning exported data manually — repeated for every question, with manifest files pulled from S3 one at a time on top.

THE BUILD

Merged two previously separate tools I'd built — a database query tool and an S3 manifest extractor — into one Python server and UI, while keeping each original tool intact and still usable on its own from the command line. Binds only to 127.0.0.1, checks the Host header against DNS rebinding, issues a random per-session token on every API call, and keeps credentials in a chmod-600 config file that's scrubbed from every error message.

THE IMPACT

Replaced manual, one-environment-at-a-time lookups with a single parallel search across all four — [X hours/week saved]. A companion module adds direct S3 manifest JSON queries — duplicate windows, cue points, active-window checks.
